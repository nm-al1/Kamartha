# Audit setelah implementasi Flutter, batch UI pertama

Tanggal: 2026-11-05. Mode yang dipilih pengguna: **AFTER**. Dokumen ini memuat
temuan untuk ditinjau, bukan izin mengubah warna atau arah desain secara sepihak.
Perbaikan bernomor berikut belum diterapkan sebagai pekerjaan audit.

## Lingkup dan arah visual

Acuan: `design/kamartha-design-responsive.figcraft`,
`design/responsive/OPENCODE-PROMPT.md`, dan
`design/responsive/HANDOFF-FLUTTER-WEB.md`. File FigCraft dibaca langsung sebagai
arsip JSON; endpoint MCP 47800 tidak aktif pada pemeriksaan. Versi lama tidak
digunakan atau diubah.

Desain dibaca sebagai aplikasi operasional satu pengelola kos, dengan Inter,
oranye identitas, kartu putih, dan navbar kapsul. Dials mengikuti audit desain
yang sudah ada: ENERGY 1 / RHYTHM 1 / MOTION 1. Bayangan navbar menandai permukaan
navigasi di luar aliran scroll, bukan dekorasi setiap kartu. Warna status mewakili
status bisnis. Pills dan Inter berasal dari arahan pengguna, bukan temuan slop.

Implementasi batch ini meliputi tema bersama, shell responsif, navbar empat tab,
Beranda, Menu, struktur Login, dan kartu daftar kamar/tagihan/pengeluaran.
Ini bukan audit selesai terhadap implementasi seluruh 28 layar FigCraft.

## Temuan yang menunggu keputusan

### 1. HIGH, R-25: pasangan warna teks normal belum memenuhi kontras AA

Sumber: `frontend/lib/app/theme/kamartha_theme.dart`,
`frontend/lib/core/widgets/kamartha_floating_nav_bar.dart`, dan warna status pada
`KamarthaRecordCard`. Contoh diperiksa pada screenshot release Chrome, termasuk
`scratch/figcraft-phase1-2026-11-05/login-390.png` dan `invoices-360.png`.

Perhitungan luminansi sRGB untuk pasangan token:

| Pasangan foreground/background | Rasio | Kebutuhan teks normal |
| --- | --- | --- |
| Putih / primary_action #FD3D18 | 3.59:1 | 4.5:1 |
| link #FE4300 / background #F3F6F9 | 3.22:1 | 4.5:1 |
| success #08964D / putih | 3.83:1 | 4.5:1 |
| danger #E53935 / putih | 4.23:1 | 4.5:1 |
| warning #FE6507 / putih | 2.97:1 | 4.5:1 |
| secondary_text #526079 / putih | 6.35:1 | 4.5:1, lolos |

Teks tombol utama 16 px dan label navbar 13 px tidak memenuhi ambang teks besar.
Angka di atas menghitung token solid, bukan klaim pengukuran setiap piksel gradien.

Usulan: pertahankan oranye identitas untuk permukaan/ikon, tetapi sepakati token
teks status/link yang lebih gelap dan pasangan teks tombol yang memenuhi AA.
Pilihan alternatif mengubah ukuran/bobot teks perlu dibandingkan kembali dengan
FigCraft. Jangan menyebut palet saat ini sudah aksesibel hanya karena sesuai desain.

### 2. HIGH, R-32: label aksesibilitas pencarian Beranda menggabungkan KPI

Pada smoke Chrome, snapshot ARIA menunjukkan textbox bernama gabungan
`Cari nomor kamar 2 dari 3 kamar dihuni 2 orang tinggal 1 kosong ...`.
Ini membuat konteks pencarian bercampur dengan statistik di kartu yang sama.
Sumber: `_hero` pada
`frontend/lib/features/dashboard/views/home_page.dart`.

Usulan: beri batas Semantics terpisah untuk field pencarian dan setiap kelompok
statistik, lalu verifikasi ulang label melalui pohon aksesibilitas. Ini belum
diuji dengan TalkBack atau VoiceOver; tidak ada klaim hasil perangkat nyata.

### 3. LOW, R-11/R-20: kesetiaan visual masih parsial

Bandingkan screenshot release di `scratch/figcraft-phase1-2026-11-05/` dengan
`design/responsive/verified/*-nav-13px.png`.

- Chip status/filter Tagihan masih memakai sebagian bentuk dan indikator bawaan
  Material, bukan seluruh bentuk pill dari FigCraft.
- Hero/Login belum mereproduksi seluruh komposisi logo dan panel persis seperti
  render acuan. Tanggal Beranda masih berformat ISO, bukan tanggal Indonesia panjang.
- Nominal kartu diletakkan di bawah rincian untuk mempertahankan keterbacaan pada
  lebar sempit; tata letak angka di kanan pada skala normal belum disamakan penuh.
- Label akses sesi dibuat fungsional lewat `Akun dan sesi`; logout yang ada tetap
  melalui layar sesi, bukan tombol keluar baru yang belum diuji.

Usulan: lakukan putaran kesetiaan visual setelah keputusan kontras; jangan
menghapus pembungkusan teks, memperkecil nominal, atau memakai data fiktif demi
menyamai screenshot statis.

## Batas API yang bukan alasan mengarang data

- Daftar kamar API saat ini mengembalikan data kamar, bukan nama penghuni per
  kamar. Pencarian hanya mendukung nomor kamar. UI mempertahankan label yang benar
  alih-alih mengklaim pencarian nama penghuni yang belum tersedia.
- API invoice menerima satu status spesifik. Filter cepat yang tersedia memakai
  Semua, Menunggak, dan Lunas; filter gabungan Belum lunas belum diklaim.
- API daftar pengeluaran tidak memberi total bulanan. Angka total bulan dan
  rentang tanggal pada screenshot desain tidak disalin menjadi data aplikasi.
- Shortcut Catat pembayaran membuka daftar tagihan agar pembayaran tetap terkait
  invoice yang dipilih. Tidak ada nominal pembayaran dummy di build aplikasi.

## Bukti dan gate

- `flutter analyze`: tidak ada isu.
- `flutter test --reporter expanded`: 54 tes lulus.
- `flutter build web --release --dart-define=API_URL=http://localhost:8001/api/v1`:
  berhasil.
- R-26, PASS terbatas: smoke Chrome mengeklik login, empat tujuan utama, Menu ke
  Pengeluaran, kembali ke Menu, sesi dan logout. Hasil tersimpan di
  `scratch/figcraft-phase1-2026-11-05/results.json`.
- R-03, PASS terbatas: tes widget layout utama memakai 320/360/390/430 px pada teks
  200%, tanpa exception layout. Login juga diuji dengan inset keyboard sintetis.
- R-35, PASS terbatas: build release dijalankan dalam Chrome headless pada
  320x568, 360x800, 390x844, 430x932, 1280x900; 30 screenshot dihasilkan.
- R-17/R-38, PASS terbatas: aplikasi tetap mengambil nilai API; fixture browser
  memakai nama/angka dummy yang hanya dicegat dalam sesi QA, tidak disimpan ke
  backend. Tidak ada bisnis Supabase yang ditulis oleh smoke browser ini.
- R-25, FAIL: temuan 1 masih terbuka. Gate rilis aksesibilitas belum lolos.
- R-32, BELUM LENGKAP: temuan 2 dan uji keyboard/pembaca layar menyeluruh masih
  terbuka. Klik otomatis bukan bukti navigasi keyboard atau audit pembaca layar.

Inspeksi visual dilakukan pada sebagian screenshot, termasuk Login 390, Beranda
320/360/1280, Menu 320, Tagihan 360 dan Pengeluaran 320/360. Tidak ada perbandingan
pixel-diff otomatis; kesetiaan piksel belum dinyatakan PASS. Screenshot browser
memakai API sintetis, bukan integrasi penuh UI dengan backend hidup.

## Putusan

**Batch implementasi dapat ditinjau, tetapi belum layak diberi label siap rilis.**
Prioritas keputusan: temuan 1 dan 2, kemudian kesetiaan visual temuan 3. Layar
detail, pembayaran/review, laporan dan formulir lanjutan tetap perlu integrasi
desain tersendiri. Tidak ada mode gelap baru atau fitur backend baru yang dibuat.
